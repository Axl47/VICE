# UI Enhancements 0.2.2

This independent module adds a square player-centered minimap, total/per-unit payments to tracked deals, map portrait pins for unlocked customers and compass markers for other multiplayer players. All four features default on. It reads existing contract/NPC/player data and creates local presentation objects; it does not change transactions, progression or saves.

## Minimap

The top-right square is a child of the gameplay HUD, with a three-unit border and 24-unit edge margin. A `RectMask2D` clips its map artwork/icons to the viewport; all graphics disable raycasts, and its `CanvasGroup` blocks no input. North stays up. The local player's complete native POI glyph is copied at the exact center, including the foreground image outside `IconContainer`, with its original colors/materials. A blue diamond is used until its UI is available. Other multiplayer players use the same complete-glyph renderer, preserving image/raw-image draw order.

Version 0.2.2 updates the local glyph's direction every visible late frame from `PlayerCamera.Camera.transform.forward`, falling back to the player's forward direction if the camera is unavailable. Horizontal X/Z determines heading; looking vertically retains the last valid heading. Current 0.4.7f10 `POI.UpdatePosition` rotates `IconContainer`, rather than the whole player UI. The minimap replaces that container's local rotation only while composing its own copied geometry, so stale native rotations while the phone is closed cannot freeze or double-rotate the indicator. Descendant offsets and rotations remain intact, and sibling/backing graphics retain their layout. Other player pins use their live POI forward direction, matching the native map's replicated orientation. No native UI, camera or player transforms are written.

`MapApp.BackgroundImage` supplies the same sprite, color and aspect setting used by the full map, including its tutorial/main-map selection. Image corners are composed through local transforms below the common ancestor with `PoIContainer`; shared phone pan/zoom/fade transforms are excluded, even when the hidden phone has zero scale. Invalid transient geometry keeps the last valid layout. `MapPositionUtility.GetMapPosition` supplies the native X/Z projection. The minimap moves only its own content by the negative player coordinate/anchor and scales it by the configured viewport width divided by world coverage and the native conversion factor. It never opens the phone, changes native scrollbars/content transforms or installs a new detour.

The uncovered viewport uses the native map's border color: `Map_Full` water pixels are RGB 50/66/76 (`#32424C`); `DesertMap` border pixels are RGB 84/77/68. These values were read from the installed 0.4.7f10 sprites. A mod-owned one-pixel texture/sprite uses the source texture's sRGB setting and map tint so linear-color rendering does not introduce a seam. It changes color only when switching map type and is destroyed with the panel.

Active native POIs belonging to the local map are reconciled once a second. Their icon `Image`/`RawImage` graphics are rebuilt as plain UI primitives, with current sprites/textures, base materials, color, fill, geometry and local visibility mirrored for nearby pins. Symbols default to 1.55 times their previous size (55% larger), including local and remote player glyphs. Large geographical search-zone shapes retain their native coverage. No `MapApp`, `POI`, button, navigation or event-listener behaviours are cloned. Native labels/tooltips are omitted from this compact view. Faraway pins skip their per-frame graphic copies; large search-zone bounds are considered before clipping. The local player's native POI is excluded from the scrolling pins so the center indicator does not duplicate it.

Position updates run in `OnLateUpdate`, following movement and teleports on the host or joining client. Known-customer POIs initialize/update when the minimap is visible as well as when the phone map is open, so opening the phone once is not required. Existing NPC eligibility and indoor entrance positions still apply. The minimap hides with the HUD, open phone or pause screen, without treating a stale `MapApp.isOpen` flag as proof the phone is visible. The existing map hook resets its refresh state on both opening and closing; returning to gameplay refreshes pins, layout and the owned clipping mask. Replaced native POI UI/icon containers invalidate their copies, so respawns or UI recreation rebuild the glyphs. It destroys its owned panel/icons and border texture during loading, scene/HUD/map replacement, disabling, mod teardown or quitting, and rebuilds for the next loaded player.

## Deal list

`QuestHUDUI.UpdateUI` and `UpdateMainLabel` independently write the native title/subtitle text in this beta. Postfixes on both methods detect a `Contract`, read `Payment`, and insert pricing before the first timing/subtitle line. Ordinary quests are left alone. The total uses grouped dollar formatting, including fractional amounts when present. Invalid payments are omitted.

The additional unit price divides `Payment` by `ProductList.GetTotalQuantity()` and rounds to one decimal, for example `$1,000 ($33.3/unit)` for 30 units. It uses requested product units, not inventory package counts. Multiple requested products produce an average across their combined quantity. An absent/empty product list or non-positive total quantity shows only the total payment, preventing division by zero.

Native refreshes rebuild the base text before the addition, so amounts do not accumulate when the time or tracking state changes. Text layout and the HUD shade are rebuilt for long names or large payments. The display is the accepted contract's base payment, before delivery-dependent bonuses or deductions.

## Customer map

The map manager reconciles `Customer.UnlockedCustomers` once a second while the map is open or the enabled minimap has a loaded player. It also requires the NPC's relationship to be unlocked and the NPC to be active/alive. The native NPC pointer deduplicates entries, including customers with multiple references. Existing potential-customer zones and quest pins remain under the game’s control.

Each marker clones the current `NPCManager.NPCPoIPrefab`, configured while inactive with its NPC, hover name and location before native UI creation. The native portrait prefab supplies its mugshot, tooltip, map-item registration, controller navigation and click-to-focus. Position updates use `POI.UpdatePosition`, which projects world X/Z through the current `MapPositionUtility` origin and conversion factor into the map's existing container. Pan/zoom therefore use the same coordinates as native pins.

Pins follow the NPC every frame while either map is active. An indoor customer uses `LastEnteredDoor` when available. Customers removed from the unlocked list, deactivated or dead lose their pin. Only mod-owned marker objects are destroyed; native `POI.OnDisable` deregisters their UI. Leaving the main scene or quitting clears references so a different save can rebuild its own markers. Markers do not write NPC transforms or spawn network objects.

## Multiplayer compass

After the native `CompassManager.Update`, the manager reconciles `Player.PlayerList` every half-second. It excludes the local player, inactive objects and players whose networking has stopped. Remote `PlayerLoaded` is not used as an eligibility gate because it is not a replicated readiness flag. The local player and player camera must be ready before creating elements.

Each marker registers through `CompassManager.AddElement` with a blue diamond. Version 0.1.2 uses that element's native `DistanceLabel` for the player name, retaining its parent, vertical position, height, font and alignment. Only its width is increased to at least 110 UI units; long names truncate with an ellipsis and rich text is disabled. The separate label above the icon is removed because it was cropped by the compass bounds in live testing.

Native `UpdateElement` still handles direction placement. Immediately afterward, the mod replaces the distance text with the cached player name on that owned element, so native refreshes cannot leave the number in place. Mission/quest labels retain their normal distance text. The marker applies the bounded opacity from native `GetCompassData`, so it fades at the compass's direction limits and follows the normal hidden/disabled compass canvas.

Targets are mod-owned, non-networked transforms updated from each peer's replicated position. They survive a disconnect until their elements are deregistered, preventing native compass updates from following destroyed player transforms. Removal uses the exact owned `Element`, then destroys its UI and target. Other compass/quest elements are not removed. Missing players, a replacement compass, the main-scene unload and application exit clean up the owned objects. Host and joining clients can display markers independently without new RPCs or save data.

## Configuration and validation

`PersonalUIEnhancements` contains `Enabled`, `ShowDealPayouts`, `ShowKnownCustomers`, `CustomerMarkerScale`, `ShowMultiplayerPlayers`, `ShowMinimap`, `MinimapSize`, `MinimapRange` and `MinimapIconScale`. The four additions can be disabled separately. `ShowDealPayouts` controls both total and per-unit pricing. Customer icon scale is bounded to 0.35–1.5, with 0.75 as the default/fallback. Minimap size defaults to 240 HUD units (160–480); range defaults to 160 world units across (60–500); symbol scale defaults to 1.55 (0.5–3). Invalid/non-finite numeric settings use the defaults. Restart after editing the configuration.

The four UI hook targets have distinct method bodies in the installed beta and pass the repository's shared-address audit. Version 0.2.2 was compiled/audited against 0.4.7f10; the original minimap targeted 0.4.7f9. Native player/compass accessors, registration/projection/teardown APIs, map/phone visibility methods, POI rotation and player-icon asset hierarchy were inspected. Compilation and native inspection do not establish appearance or multiplayer behavior in the live game. See `playtest.md` for minimap, pricing, compass, map navigation and scene cleanup checks. Installation remains manual.
